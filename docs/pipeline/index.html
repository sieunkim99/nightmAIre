02. 생성은 일곱 단계, 아이의 경험은 세 덩어리

아이에게 보이는 앞부분

재료 이야기하기

내 경험 또는 상상 → 필요한 질문 → 내 말 확인

아이의 창작 참여

꿈에 데려갈 것 고르기

세계 씨앗 → 섞거나 바꾸기 → 베개 밑 쪽지

완성 경험

꿈 읽기·나오기

내용에 맞는 장면 → 덜 무섭게 보기 → 명확한 종료

되돌아가는 경로: ②에서 중요한 조건이 비면 ①로 확인 질문 · ④에서 새 가정을 넣으면 ③을 수정 · ⑥에서 근거·연결 오류가 발견되면 ⑤ 또는 ③으로 · 그림 실패는 해당 그림만 재시도

계산 단계를 나누는 이유와 완료 조건

한 번의 writer 호출에 위험 검색·미래 확장·꿈 연출을 모두 맡기면 단계별 오류를 찾기 어렵다. 각 단계는 고유 ID가 있는 결과를 남기고 다음 단계는 그 결과를 입력으로 받는다. 위험 후보가 없으면 새 근거를 만들어내지 않으며, 검토에서 실패한 결과는 아이에게 정상 결과처럼 전달하지 않는다. 모델 검토는 연구자의 문헌 검토를 대신하지 않는다.

03. 카드는 ‘논문에서 나온 악몽 줄거리’가 아니다

분류는 무엇을 찾아볼지 알려준다. 메커니즘은 어떤 조건에서, 무엇을 거쳐, 어떤 결과가 가능해지는지를 설명한다. 카드 화면은 이 둘을 모아 읽는 창이다.

출처 R논문·버전·원문 위치
주장 C대상·과제·결과·한계
기제 M조건·과정·대안
미래 F가정·사건·행위자
꿈 D세계·장면·은유

연결에도 종류가 있다

연구가 지지함관찰된 연관적용상의 추론새 가정꿈속 전환

같은 연구를 인용한 두 노드라도 그 사이의 인과관계가 입증된 것은 아니다. 시간 점프와 파급의 차수도 별개다.

반대 조건도 생성에 쓰인다

정답을 그대로 받기와 먼저 풀고 힌트를 받기는 다른 경로로 가야 한다. 반대 증거를 각주에만 두고 항상 같은 파국을 생성하면 기제 연결이 실패한 것이다.

문헌의 역할채택경계
YAIR청소년 위험 영역·상호작용 경로를 검색하고 누락 점검분류 자체로 아이의 미래를 예측하지 않음
MIT AI Risk Repository위험 영역과 발생 주체·의도·시점을 구분하는 보조 축원인 분류표가 검증된 개별 인과모형은 아님
개별 실증 연구특정 주장과 적용 조건·반대 조건을 채움성인·고등학생·단기 결과를 초등 장기 효과로 일반화하지 않음
TSJ/CDM발달 맥락을 생각하는 참고 렌즈시뮬레이션 자료를 실제 아동 장기 추적처럼 사용하지 않음
‘YAIR 13개 전부’는 수정해야 한다.
정식 SOUPS 2025 PDF의 Table 3은 중간 항목 14개를 열거하고 Figure 1 설명은 15개라고 표기한다. 이전 arXiv/HTML 설계의 13개와 구분해 버전·대응표로 관리한다. 84개 세부 위험을 전부 검증·구현했다는 의미가 아니다.
기존 16장을 어디로 옮기는가

시스템 특성·사건: sycophancy, hallucination, holdme, changed.
상호작용·판단: outsourcing, overreliance, informant, personhood, nudge, nextvideo, easier.
결과·패턴: memorygap, dependence, sameness.
복수 경로로 분해: fakes, secrets.

이 분류는 프로젝트의 데이터 구조를 위한 재배치다. 각 개념은 하나 이상의 메커니즘과 연결될 수 있다. 기존 카드와 출처는 보존하되 미검토 내용을 검증 완료로 승격하지 않는다.

04. 조건을 바꾸면 미래도 바뀐다

설명용 사례: “수학 숙제를 빨리 끝내고 게임하고 싶었어.” 아래에서 AI 도움을 사용한 방식을 바꿔 보면, 같은 바람이 다른 미래 조건으로 이어지는 것을 볼 수 있다.

꿈으로 바꾸는 순간: 아이의 지우개가 경계를 지운다

아이가 A와 B를 섞으면, 자동으로 완성되는 답안이 도장 계단을 끝없이 만든다. 위층으로 올라간 주인공이 아래 친구에게 풀이를 설명하려 하자, 글자가 입가에서 종이 조각으로 흩어진다.

“지우개로 학교 두 개를 합칠래”라는 아이의 재료는 세계의 연결을 실제로 바꾼다. 지우개·목소리·계단의 규칙은 창작 은유이며 연구가 입증한 사건이 아니다. 비교 세계 C를 최종 꿈에 넣을지는 선택에 달려 있다.

근거 R1: Bastani et al., 2025. 특정 고등학교 수학 실험에서 도구의 지원 방식에 따라 결과가 달랐다. 이 사례의 초등학생·학교 제도·미래 세계는 연구를 넘어선 설계 가정이다.

05. 꿈 제작소와 베개 밑 쪽지

아이에게 하는 설명

“네가 이야기해 준 조각과 ‘만약’을 섞어서 꿈을 만드는 곳이야. 꿈에 꼭 데려가고 싶은 것도 넣을 수 있어. 이건 앞으로 꼭 생길 일이 아니라, 우리가 함께 만드는 상상이야.”

안내자는 짧고 호기심 있게 묻는 제작 도우미다. 속마음을 알아맞히는 전문가나 아이에게 의존을 요구하는 친구 역할을 맡지 않는다.

세 가지 재료의 역할

  1. 기억 쪽지: 아이가 말하고 확인한 경험·바람
  2. 만약 쪽지: 학교·AI·관계에서 바꿔 보고 싶은 조건
  3. 꿈에 데려갈 것: 물건·말·상상 조각, 꿈의 전환을 만드는 재료

베개 아래에 넣기는 클릭·선택으로도 가능하다. 물건 3개나 드래그 동작을 필수로 만들지 않는다.

두 Notion 페이지의 재료 수집·꿈 제작소·베개 밑 쪽지를 연결한 제안이다. 다른 아이의 실제 재료 공유는 단독 사용 기본 흐름에 넣지 않는다. 필요하면 검토된 가상 조각을 제공한다.

연구에서 차용하는 범위: Dormio는 실제 수면 시작 단계에서 자극이 꿈 내용에 들어가도록 하는 연구다. 이 서비스는 깨어서 쓰는 창작 도구이므로 실제 꿈 배양 장치도, 무의식 분석도 아니다. 위협 시뮬레이션은 꿈의 기능에 대한 가설이다. 인공 악몽을 보여주면 아동의 성찰·정서 조절이 향상된다고 주장하지 않는다.

06. 여러 세계를 꼭 ‘갈림길 게임’으로 보여줄 필요는 없다

첫 코드 시안에는 생성 전에 함께 고르고, 완성 후 한 편으로 읽기를 임시 기본값으로 둔다. 혼자 쓰는 아이가 이야기의 연결을 이해하는지 먼저 확인하려는 개발 판단이다. 최종 형식은 아래 결정 목록에서 정하며, 세계·장면·전환을 담는 공통 결과 구조는 유지한다.

08. 구현 순서와 확인할 동작

  1. 문서 먼저: 변경 전후, 단계별 입력·출력, 분류 대응, 결정 목록을 sieun에 기록한다.
  2. 생성 코드: 경험 → 근거 연결 → 여러 미래 → 공동 선택 → 세계·장면 → 집필을 실제 요청으로 연결한다. writer가 전체 덱에서 새 위험을 임의로 다시 고르지 않는다.
  3. 단독 사용: 요약 수정·건너뛰기·나오기, 선택 위임, 명확한 끝을 제공한다. 되돌리기 단계로 강제 이동시키지 않는다.
  4. 검사: 출처·사건 참조가 유효한지, 선택이 반영되는지, 장면 수가 달라져도 읽히는지, 실패가 데모로 숨겨지지 않는지 확인한다.
  5. 그다음: 실제 생성 품질·아동 사용성을 검토하고 자료 보존·운영 방식과 배포를 정한다.

구현 확인과 연구적 검증은 다르다. 구조 검사를 통과해도 문헌 해석과 아동 적합성이 검증된 것은 아니다. 유해 현실 경험의 처리와 검토되지 않은 위험 경로는 운영 전에 별도로 확인한다. 현재 구현·호출 수·검사·남은 작업 보기
