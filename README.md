# nightmAIre · 꿈 제작소

초등 5–6학년이 혼자 자신의 경험이나 상상을 재료로 여러 가능한 미래를 골라 꿈을 만드는 **연구·디자인 프로토타입**이다. 꿈은 예측이나 진단이 아니다. 이번 범위는 생성과 읽기까지다.

## 생성 경로

```text
경험·상상·예시 구분 → 아이의 원문 확인
  → 조건부 기제 연결 (한 번 확인 질문 / 부적합하면 재료 변경)
  → 서로 다른 가정의 미래 후보와 사건·연결 생성
  → 아이가 1–3개 선택 + 선택적 ‘만약’ 쪽지·사물
      새 가정이 있으면 선택한 미래 그래프부터 수정
  → 세계별 규칙·전환·읽기 순서 + 이야기 생성
  → 구조 검사 + 별도 모델 검토 (실패 시 1회 수정, 재실패는 오류)
  → 텍스트 먼저 전달 → 그림 별도 준비 → 읽기·종료
```

6장면, 규칙 하나, 정확히 세 번 반복은 요구하지 않는다. 장면 수는 가변이며 20장은 프로토타입 자원 상한이다. 생성 전에 선택하고 완성 후 한 편으로 읽는 형식은 **임시 기본값**이다. 성찰 과제·되돌리기는 현재 흐름에 연결하지 않는다.

YAIR 정식 PDF Table 3의 **14개 분류**와 **생성용 기제 3종**을 구분한다. 독립적 시도 대체, 미검증 출력 수용, 관계 활동 대체의 조건부 해석부터 연결했다. 논문 → 주장 → 기제 → 미래 사건 → 꿈 장면의 참조와 적용 한계를 보존한다. 문헌 분류나 모델 검토를 인과·아동 효과의 검증으로 간주하지 않는다.

## 실행

```bash
npm install
cp .env.example .env
npm run dev
```

웹은 `http://localhost:5173`, API는 `http://localhost:5799`. `.env`에서 서버용 모델 키를 설정한다. 기존 모델 기본값을 유지했으며, 실제 계정에서 사용 가능한 모델과 비용을 운영 전에 확인한다. 키를 저장소에 넣지 않는다.

서버가 켜져 있으면 [설계 문서](http://localhost:5799/docs/pipeline/)도 별도 주소에서 열 수 있다.

- `DEMO_MODE=1` 또는 텍스트 모델 키 없음: **준비된 가상 예시**라고 표시한다. 선택한 세계·사물은 연결하지만 자유 쪽지로 새 미래를 생성하지 않는다.
- 라이브 요청 실패: 오류와 재시도를 보여준다. 다른 데모로 대체하지 않는다.
- 이미지 키 없음 또는 `NIGHTMAIRE_IMAGES=0`: 캔버스 연출로 읽는다. 이미지가 켜져도 텍스트 읽기는 먼저 가능하다.
- `ACCESS_CODE` 설정 시 생성·라이브러리 API에 접속 코드를 요구한다. 코드는 브라우저 세션에만 남긴다.

```bash
npm test
npm run build
npm start
```

## 데이터와 검증 범위

원문·선택·이야기를 앱의 localStorage나 연구 로그에 영구 저장하지 않는다. 서버 임시 메모리는 30분 후 만료하며 다음 정리 주기(최대 1분)에 삭제한다. 종료 요청도 해당 참조를 삭제한다. 메타데이터 로그는 기본 꺼짐이고 `NIGHTMAIRE_RECORD_METADATA=1`일 때 원문 없이 단계·모드·장면 수 등만 남긴다.

**이미지 파일은 별도다.** 생성 이미지는 `server/data/images`에 남으며 자동 삭제·접근 통제 개편은 미구현이다. 모델 제공자의 데이터 처리·보존 정책도 앱 메모리 정책과 별개다. 동의·보존·삭제·접근 방식은 실제 아동 참여 전에 정할 사항이다.

자동 검사는 참조 무결성, 선택 보존, 새 가정 반영, 가변 장면, 명시적 실패를 확인한다. 실제 모델의 서사 품질, 문헌 해석의 타당성, 이미지 적합성, 아동 단독 사용성은 별도로 검토해야 한다. 이번 변경은 호스팅 배포나 Supabase 이전을 수행하지 않는다.
